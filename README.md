# ウマ娘 ズームクイズ

拡大されて一部しか見えないキャラクター画像から、どのウマ娘かを当てるブラウザゲーム。

## 遊び方

```bash
node tools/serve.mjs
```

`http://localhost:5173/` を開く。

> `index.html` をダブルクリックして `file://` で開いても遊べますが、画像CDNのCORS設定次第では
> 「透明領域を避けた賢いトリミング」が無効化され、余白が出題されることがあります。
> ローカルサーバー経由での起動を推奨します。

## 操作

| 操作 | 内容 |
| --- | --- |
| 名前を入力 | ひらがな・カタカナ・英語（`gold` → ゴールドシップ 等）でサジェスト |
| ↑↓ + Enter | 候補を選んで回答 |
| ズームアウト | 表示範囲を1.7倍に広げる（-25点・最大3回） |
| ヒント | CV・区分・衣装名を表示（-20点） |
| ⚙ | ゲーム中に押すと中断して結果へ |

スマートフォンにも対応。縦向きは1カラム、横向き（縦が短い画面）ではステージを左・操作を右に置く
2カラムに切り替わる。ステージの大きさは `svh` 基準なので、ソフトキーボードが開いても縮まない。

### 共有

結果画面から、Wordle 風の絵文字グリッドつきで共有できる。

```
ウマ娘 ズームクイズ 🔍
むずかしい / ウマ娘のみ
740点　4/5問正解（80%）

🟩🟨🟥⬜🟩

#ウマ娘ズームクイズ
```

| ボタン | 動作 |
| --- | --- |
| 𝕏 でポスト | X の投稿画面を開く（実際のポストは自分で確認して送信） |
| 共有 | `navigator.share` が使える端末（主にスマホ）でのみ表示 |
| 結果をコピー | クリップボードにコピー |

🟩 ノーヒント正解 / 🟨 ヒント・ズームアウト使用 / 🟥 不正解 / ⬜ パス

### 得点

`基礎点 100 -（ズームアウト 25 × 回数）-（ヒント 20）` に、連続正解ボーナス（連続数 × 10、上限50）を加算。
難易度・出題範囲・問題数ごとに自己ベストが `localStorage` に保存される。

### 難易度

画像の短辺に対して表示する割合。

| | 表示範囲 |
| --- | --- |
| やさしい | 20% |
| ふつう | 12% |
| むずかしい | 7% |
| 鬼 | 4% |

## 構成

```
index.html            画面
styles.css            スタイル
game.js               ゲームロジック
data/characters.js    キャラクター情報と公式画像URL（自動生成）
tools/fetch-characters.mjs  データ生成スクリプト
tools/serve.mjs       確認用の簡易静的サーバー
```

### データの更新

新キャラ追加時などは再生成する。

```bash
node tools/fetch-characters.mjs
```

公式ポータル（umamusume.jp）の Nuxt ペイロードから、キャラ名・CV・区分と
ビジュアル画像（1125×1980）のURLを収集して `data/characters.js` を書き出す。
現在 170人 / 560枚。

### 出題部分の選び方

画像を 72px 幅に縮小して各セルの α 値と輝度勾配を調べ、

- 周囲3×3がすべて不透明（α ≥ 0.85）なセルだけを候補にする → 透明な余白が出題されない
- 輝度勾配が大きいセルほど重みを大きくする → のっぺりした面より、瞳・髪飾り・模様などが選ばれやすい

という重み付き抽選で拡大位置を決めている。この処理には canvas でのピクセル読み取りが必要なため、
画像は `crossOrigin="anonymous"` で読み込んでいる。

拡大は canvas ではなく `transform: translate() scale()` で行っているので、ステージの大きさが
変わったら scale を計算し直す必要がある。アドレスバーの伸縮や向き変更は `window.resize` だけでは
取りこぼすため、`ResizeObserver` と併用してステージの実寸を監視している。

## 公開する（GitHub Pages）

`.github/workflows/deploy.yml` が用意してある。`main` に push すると、
`index.html` / `styles.css` / `game.js` / `data/characters.js` / `robots.txt` だけを
配信用にまとめてデプロイする（`tools/` や `.claude/` は含めない）。

1. GitHub でリポジトリを作り、push する

   ```bash
   git init -b main
   git add -A
   git commit -m "ウマ娘ズームクイズ"
   git remote add origin git@github.com:<user>/<repo>.git
   git push -u origin main
   ```

2. リポジトリの Settings → Pages → Build and deployment → Source を
   **GitHub Actions** に変更する
3. Actions タブでデプロイの完了を待つ
4. `https://<user>.github.io/<repo>/` で公開される

パスはすべて相対なので、サブディレクトリ配信でもそのまま動く。

### 身内用にするための注意

GitHub Pages は**サイトそのものは必ず公開**され、URLを知っていれば誰でも開ける。
無料アカウントの場合はリポジトリも public になるため、プロフィールから存在を辿られる。
実質的な保護は次の2つだけ。

- `robots.txt` と `<meta name="robots" content="noindex, nofollow, noarchive">` で検索避け（設定済み）
- URLを身内以外に共有しない

ちゃんと閲覧者を絞りたくなったら、Cloudflare Pages + Cloudflare Access に移すと
無料枠のままメールアドレスの許可リストで制限できる。ファイル構成はそのまま使える。
